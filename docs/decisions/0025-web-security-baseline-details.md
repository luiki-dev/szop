# ADR 0025 — Web security baseline details

- **Status:** ✅ Accepted
- **Date:** 2026-10-10
- **Refines:** [ADR 0012](0012-security-baseline.md), decisions 7 (unsafe requests with neither header, the Origin fallback, JSON-only bodies through Fastify's parsers, see decisions 1 to 3), 8 (the CSP written out, HSTS's subdomains, the build's inline limit, see decisions 4 and 5), 9 (every query value hidden in the log, tokens only in the query, see decision 6) and 13 (the proxy trusted by address, TRUSTED_PROXIES, instead of a hop count, see decision 7)

## Context

[PH-06b](../roadmap.md#ph-06b-web-security-baseline) puts the web security baseline in place before the first endpoint that changes data exists: the security headers on every response, the check that unsafe requests come from the app itself, JSON-only bodies, the client address behind the load balancer and tokens kept out of the log. It was split from PH-06, now retired, which also held the production build, now [PH-06a](../roadmap.md#ph-06a-production-build-and-serving) ([ADR 0014](0014-roadmap.md), decision 6). [ADR 0012](0012-security-baseline.md), decisions 7, 8, 9 and 13 set its direction; its brainstorm and the [spec](../superpowers/specs/2026-10-10-PH-06b-web-security-baseline-design.md) settled the details. Decisions 1 to 6, 8 and 9 were taken in the brainstorm. Decision 7 was found while planning: a probe showed that Fastify 5.12, the version in use, ignores a hop count for `trustProxy`, so the mechanism ADR 0012, decision 13 planned no longer works. The "settled while building" notes in the cells came from the implementation.

## Decisions

| # | Topic | Options considered | Decision and reasoning |
|---|-------|--------------------|------------------------|
| 1 | An unsafe request with neither `Sec-Fetch-Site` nor `Origin` | Let it through, as Go's `net/http.CrossOriginProtection` does; refuse it | **Refuse it with 403, as [ADR 0012](0012-security-baseline.md), decision 7 says.** The only allowed unsafe requests carry `Sec-Fetch-Site: same-origin`, or, without that header, an `Origin` whose host is the request's `Host`. Letting such requests through is sound reasoning: every browser of [NFR-1](../requirements/functional-requirements.md#nfr-1) sends `Sec-Fetch-Site`, so a request with neither header is not a browser and cannot be cross-site request forgery (CSRF), which is a browser sending the user's cookie for another site. But it would change an accepted decision for convenience only: nothing sends unsafe requests from outside a browser today (the load balancer's health check is a GET), refusing fails closed if a browser setup ever strips both headers, and the cost is one header in tests and in `curl`. **Revisit** when a non-browser client must send unsafe requests, such as a webhook or a native app; that phase decides an exemption and records it. The check defends against a malicious site steering the user's browser, nothing else: page scripts cannot set `Sec-Fetch-Site` or `Origin`, but any other program can, so scripts calling the API directly are met by sessions, rate limits and quotas. |
| 2 | What the `Origin` fallback compares with | The request's raw `Host` header; Fastify's `request.host`; a new `APP_ORIGIN` setting | **The host of the `Origin` header against the raw `Host` header**, as Go's check does. `request.host` reads `X-Forwarded-Host` once a proxy is trusted, which is one more header to reason about. An `APP_ORIGIN` setting would be needed by nothing else before PH-18, where Better Auth's base URL may bring one. An `Origin` that is not a URL, such as `null`, is refused. <br>**Settled while building:** the comparison is of `host` with its port, so `http://localhost:5173` is refused by an app on `localhost:3000`; a test pins it. Browsers leave a default port out of both headers, so they still match. |
| 3 | How bodies are kept to JSON | A hook checking `Content-Type` on unsafe methods; removing Fastify's `text/plain` parser | **Remove Fastify's `text/plain` parser**, leaving `application/json` as the only body Fastify parses; every other content type gets Fastify's own **415 Unsupported Media Type**. The content types an HTML form can send (`application/x-www-form-urlencoded`, `multipart/form-data`, `text/plain`) are the browser's "simple requests", which reach the server without a CORS preflight; this closes them with Fastify's own mechanism and no custom code. A request without a body passes: there is nothing to be non-JSON, and a real `DELETE /api/lists/:id` has no body. A cross-site DELETE without a body is impossible from a form, needs a preflight from `fetch`, and is refused by decision 1 anyway. <br>**Settled while building:** a POST with a body and no `Content-Type` gets Fastify's 415 too, pinned by a test, and so does a form content type with an empty body (probed); a DELETE without a body passes, pinned by a test. |
| 4 | How the CSP is written | Helmet's default policy with overrides; the whole policy written out, helmet's CSP defaults off | **The whole policy written out, with `useDefaults: false`:** `default-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, exactly [ADR 0012](0012-security-baseline.md), decision 8. Scripts, styles, fonts, images and `fetch` fall back to `default-src 'self'`. Helmet's defaults allow `style-src 'self' https: 'unsafe-inline'`, which is exactly the inline style ADR 0012 and [ADR 0013](0013-visual-design.md), decision 9 rule out, plus `data:` fonts and images; with overrides, the effective policy would be half helmet's version-dependent defaults, readable only in its source. Written out, the policy sits in one place, the test asserts the exact header, and an upgrade of helmet cannot change it. **The build stays inside it:** `build.assetsInlineLimit: 0` in `apps/web/vite.config.ts` stops Vite from inlining small assets as `data:` URIs, which `'self'` blocks. Nothing is inlined today, so the build is unchanged; small assets would become fingerprinted files, cached for a year, at the cost of one request each the first time, and they would no longer count against the first-screen budget of [NFR-3](../requirements/functional-requirements.md#nfr-3). An explicit `?inline` import still inlines, and the CSP and PH-07's guard would catch it. <br>**Settled while building:** helmet 8 joins the directives with `;` and no space, which the test pins in the exact header. `pnpm build` wrote the same files before and after `assetsInlineLimit: 0` (the first screen still `109.8 KB Brotli of 200.0 KB`). The tests prove the headers on `@fastify/static`'s files, on `index.html`, on the not-found handler's JSON 404 and on the cross-site check's 403. One response goes without them: Fastify answers a malformed path, such as `GET /%E0%A4%A`, with a JSON 400 from its bad-URL handler before any `onRequest` hook, so helmet never runs; a JSON body has nothing to protect, so the exception is accepted. |
| 5 | HSTS and subdomains | Keep `includeSubDomains`, helmet's default; leave it out | **Keep it:** `max-age=31536000; includeSubDomains`, without `preload`. Every subdomain below the app's host name must then be HTTPS, which suits a demo served only over HTTPS and planned with no HTTP-only sites on its domain. If the app ends up on a subdomain of another domain ([PH-10](../roadmap.md#ph-10-domain-and-base-infrastructure)), only the subdomains below it are covered. |
| 6 | How tokens are kept out of the log | Hide every query value and keep the names; hide only listed parameter names; drop the query string | **Hide every query value, keep the names:** `/reset-password?token=abc&next=/lists` is logged as `/reset-password?token=[redacted]&next=[redacted]` (a parameter without a value is hidden whole: `?abc123` is logged as `?[redacted]`). A new token parameter is covered the day it appears, and the log still shows which parameters a request carried. The API reads no query values today, so nothing useful is lost; a phase that wants a value in the log adds an exception with its reason. A list of names fails silently when a phase forgets to extend it, the leak [ADR 0012](0012-security-baseline.md), decision 9 guards against; dropping the query loses the names too. **Tokens travel in the query string, never in the path,** so the rule covers them: Better Auth's default reset link puts the token in the path (`/reset-password/<token>`), so PH-18 and PH-29 build their own links through Better Auth's email callbacks ([OP-055](../open-points.md#op-055)). <br>**Settled while building:** Fastify's error line for a route that throws carries the request too, and the same serializer hides its query; a test pins it. The serializer covers every line that carries the request, but not Fastify's own warnings about programming errors: for a reply sent twice, both the `FST_ERR_REP_ALREADY_SENT` error and the matching warning put the raw URL in the message itself. Nothing does that today, since no route both calls `reply.send()` and returns a value; Better Auth's token routes make it realistic, so PH-18 extends the end-to-end "token never in the log" test to them ([OP-053](../open-points.md#op-053)). |
| 7 | How the proxy is trusted (found while planning) | A number of hops, `TRUSTED_PROXY_HOPS`, as [ADR 0012](0012-security-baseline.md), decision 13 planned; a custom trust function counting hops; the proxy's addresses, `TRUSTED_PROXIES`; addresses and a hop count | **The proxy's addresses: `TRUSTED_PROXIES`,** a comma-separated list of IP addresses and Classless Inter-Domain Routing (CIDR) ranges, or the keyword `none`. Required and validated at startup like every setting ([ADR 0019](0019-api-skeleton-details.md), decision 2); an empty value is refused, so "trust nothing" is written out as `none`, as `.env.example` does locally. In AWS it is the VPC's range, which PH-12 takes from Terraform. It is passed to Fastify's `trustProxy` as an array (`none` as an empty one, which trusts nothing), never `true`. **Why not hops:** a probe while planning showed that Fastify 5.12, the version in use, ignores a number for `trustProxy` and trusts nothing, because a hop count cannot tell whether the connection really comes from the proxy: a client reaching the app directly could send a forged `X-Forwarded-For` and have its last entry trusted. With addresses, Fastify walks `X-Forwarded-For` from the right only while the address it is looking at is a trusted proxy, so the client address is the one the load balancer appended, and a client connecting directly keeps its own address whatever it sends. A custom function counting hops would rebuild the pattern Fastify removed, against its documentation, and be safe only while the security group blocks direct access; adding a hop count to the addresses adds nothing with one load balancer. The goal of ADR 0012, decision 13 is unchanged; its mechanism is refined. <br>**Settled while building:** a proxy seen as an IPv4-mapped IPv6 address (`::ffff:10.0.1.5`) matches its IPv4 range (`10.0.0.0/16`); a test pins it. A `/0` prefix (`0.0.0.0/0`, `::/0`) is every address, "trust everything", so startup refuses it; a test pins it. |
| 8 | Where the code lives | One `security/plugin.ts` with the log module beside it; everything in `app.ts`; one file per concern | **A `security/` folder with one file per concern** (`headers.ts`, `cross-site.ts`, `json-only.ts`, `log.ts`), each with its test beside it, next to `health/` and `web/`. Each concern can be read alone, and everything ADR 0012, decisions 7–9 and 13 ask for is in one folder. `app.ts` stays a short list of what the app is made of. **Each plugin is wrapped with `fastify-plugin`**, the Fastify team's helper that turns off encapsulation, so its hooks and its parser change reach every route, the SPA's files and the not-found handler included; a plain function called on the root app would do the same without the dependency, but is the less idiomatic path. |
| 9 | How tests read the log | An optional log destination in `AppDeps`; asserting `request.ip` through a test route | **An optional `logStream` in `AppDeps`**: production leaves it out and logs to stdout, tests pass an in-memory stream and read the JSON lines back. It proves end to end what matters: the URL the log actually holds, and the `remoteAddress` it records. It follows [ADR 0007](0007-testing-strategy.md), decision 14: what the app needs from outside comes in through `buildApp`. |

## Consequences

- **Every developer's `apps/api/.env` needs `TRUSTED_PROXIES`,** since every setting is required: an `.env` made before this phase must gain the line `TRUSTED_PROXIES=none` from `.env.example`, or the API and the tests stop with `TRUSTED_PROXIES: missing`.
- **[PH-12](../roadmap.md#ph-12-first-deploy) sets `TRUSTED_PROXIES` to the VPC's range,** taken from Terraform, and checks once on the demo that the log shows the real client address behind a forged `X-Forwarded-For` ([OP-053](../open-points.md#op-053)).
- **Tests send `Sec-Fetch-Site: same-origin` on unsafe requests,** or the cross-site check answers 403 before routing, and so must a `curl` that changes data on a running app. The [testing guide](../development/testing.md) says how.
- **A non-browser client that must send unsafe requests,** such as a webhook or a native app, needs a decision of its own: the phase that brings it decides an exemption from decision 1 and records it.
- **[PH-18](../roadmap.md#ph-18-registration-and-login) and [PH-29](../roadmap.md#ph-29-password-reset-and-change) build their own email links** with the token in the query string, through Better Auth's email callbacks, instead of its path-token default (decision 6, [OP-055](../open-points.md#op-055)).
- **The 403 and the 415 use Fastify's error shape** until [OP-071](../open-points.md#op-071) settles the app's own.
- **`@fastify/helmet` 13.1.2 (on helmet 8.3.0) and `fastify-plugin` 6.0.0 are new dependencies** of the API; none has an install script, so `allowBuilds` is unchanged ([ADR 0012](0012-security-baseline.md), decision 18). `fastify-plugin` is declared as `^6.0.0`, not `^6.0.1` as the plan said: 6.0.1 was published on the day of the change, and pnpm 12's minimum release age would have needed a `minimumReleaseAgeExclude` entry in `pnpm-workspace.yaml`, an exemption from the supply-chain rule nobody had approved. The spec binds major 6 only; 6.0.0 was already in the lockfile through `@fastify/helmet`, and Dependabot can bring 6.0.1 later.
- **Open points:** the PH-06b part of [OP-053](../open-points.md#op-053) is ✅ done, its text says `TRUSTED_PROXIES`, its PH-12 part also sets the setting from Terraform, it gains PH-18 and PH-20 parts (Better Auth and the rate limiter handed the same client address and tested against a forged header; in PH-18 also Better Auth's `baseURL` set explicitly and the "token never in the log" test extended to its token routes, see decisions 2 and 6), and it moves to PH-12; [OP-055](../open-points.md#op-055) gains the email links built by the app and the SPA removing a used token from the address bar; [OP-071](../open-points.md#op-071) gains a note on the 403 and the 415; [OP-067](../open-points.md#op-067) moves to [PH-07](../roadmap.md#ph-07-first-e2e-journey), since it does not depend on this phase.
