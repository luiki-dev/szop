# ADR 0026 — First E2E journey details

- **Status:** ✅ Accepted
- **Date:** 2026-10-11
- **Refines:** [ADR 0007](0007-testing-strategy.md), decision 15 (the reset once per run is done by the start script, and the E2E server runs on its own port, see decisions 2 and 6); [ADR 0010](0010-ci-cd.md), decision 9 (the Playwright browsers are installed every run, not cached, see decision 5)
- **Extends:** [ADR 0007](0007-testing-strategy.md), decision 18 (the `test:e2e:report` script, see decision 2)

## Context

[PH-07](../roadmap.md#ph-07-first-e2e-journey) adds the first end-to-end (E2E) test layer: a real browser drives the production build on desktop Chromium, desktop Firefox and an emulated phone, checks the page with axe in light and dark mode, and fails on any Content Security Policy (CSP) violation. [ADR 0007](0007-testing-strategy.md) (decisions 4, 5, 6, 11, 15, 17, 18 and 21), [ADR 0010](0010-ci-cd.md) (decisions 7 and 9) and [ADR 0013](0013-visual-design.md) (decisions 2, 3 and 9) set its direction; its brainstorm and the [spec](../superpowers/specs/2026-10-11-PH-07-first-e2e-journey-design.md) settled the details. Decisions 1 to 9 were all taken in the brainstorm. The "settled while building" notes on decisions 2, 3, 6 and 7 came afterwards: decision 2's from the report script the owner added, the others from the implementation. The CSP guard's first run found a real violation (decision 7), and the start script's shutdown and the axe helper's import differ in detail from what was planned (decisions 3 and 6).

## Decisions

| # | Topic | Options considered | Decision and reasoning |
|---|-------|--------------------|------------------------|
| 1 | Open points outside E2E | Keep them in PH-07; move them | **[OP-067](https://github.com/luiki-dev/szop/issues/27) moves to PH-08** with the same "does not depend on that phase" note: GitHub shows no Dependabot PR yet, so PH-07 cannot close it. [OP-086](https://github.com/luiki-dev/szop/issues/156) is a process decision, a second concept for the phase; it stays in the PH-08 group and is taken as an ADR-only PR after PH-07 merges. |
| 2 | What `pnpm test:e2e` runs against | The script builds first; Playwright's `webServer` builds, then starts; the developer builds by hand | **The script builds first:** `pnpm build`, then `playwright test`. It always tests the code as it is, and CI runs the same script. A build inside `webServer` counts against the server's timeout and hides its errors; building by hand makes a stale `dist/` easy to test. **The server runs on its own port, 3100, and starts fresh every run** (`reuseExistingServer: false`), so a running `pnpm start` on 3000, with the development database, is never tested by mistake. <br>**Settled while building:** `pnpm test:e2e:report` opens the last run's HTML report, or a report folder given as its argument, such as one downloaded from CI. |
| 3 | How axe scans light and dark | A helper scanning both schemes; six projects (three, each in both schemes); an automatic scan after every navigation | **A helper, `expectAccessible(page)`,** called by the journey on every page it reaches, scans in light, then in dark. Six projects double every run for what is almost always a contrast problem, which the helper catches. An automatic scan cannot tell when a single-page application (SPA) has finished rendering a screen, so it would scan half-loaded pages. <br>**Settled while building:** the helper imports `{ AxeBuilder }` by name: under the repository's `nodenext` module resolution the default import of `@axe-core/playwright` is typed as the module namespace, so it is not constructable for the type checker, though it runs. The terminal's `list` reporter does not show the `axe (light)` and `axe (dark)` steps; the HTML report and the trace do. |
| 4 | Retries | None; two in CI (Playwright's default); one in CI with flaky tests failing the job | **One retry in CI, with `failOnFlakyTests: true`; none locally.** The check stays red for a flaky test, as [ADR 0007](0007-testing-strategy.md), decision 16 wants, and the report labels each failure *flaky* (passed on its retry) or *failed* (failed twice), with a trace of each attempt. Two retries turn the check green and hide the flakiness. |
| 5 | Playwright's browsers in CI | Cached, as [ADR 0010](0010-ci-cd.md), decision 9 said; installed every run; Playwright's container image | **Installed every run, not cached:** `playwright install --with-deps chromium firefox`. Restoring the cache takes about as long as the download, and the system libraries come from `apt`, which cannot be cached; Playwright's CI documentation advises the same. The container image's tag must match `@playwright/test` exactly, and `docker compose up --wait` ([ADR 0020](0020-database-details.md), decision 6) is awkward inside a container job. The install step's time is noted in the PR; if it dominates the job, the cache or the image comes back. **Refines ADR 0010, decision 9.** |
| 6 | Server and database | One start script reading `apps/api/.env`; a separate `e2e/.env` with a reset step in the script; importing the API's test helpers | **One start script, `e2e/start-server.ts`:** it resets `szop_e2e`, then starts the API with the settings of `apps/api/.env` and the E2E overrides merged in one visible expression, `{ ...process.env, ...fileEnv, ...overrides }`, rather than through `--env-file`, whose precedence rule (the environment wins over the file) is invisible in the code. Being one script, the reset always comes before the start, whether the run starts from the command line, the editor or CI. A second `.env` would drift from the first; importing from `apps/api/src/test/` would couple `e2e/` to another package's private test folder. <br>**Settled while building:** Playwright stops its `webServer` by signalling the whole process group (`process.kill(-pid, signal)`), so the API receives the `SIGTERM` itself. `start-server.ts` catches `SIGINT` and `SIGTERM` only to outlive the API, and never relays them: a relayed second signal would reach the API after `server.ts`'s `process.once` handler is used up, and kill it mid-shutdown. Playwright reports "already used" only when something answers `/api/health` with a status from 200 to 403; anything else on port 3100 lets the server start, and the API then fails with `EADDRINUSE` and logs `startup failed`. Either way no test runs against the wrong server. |
| 7 | The CSP guard | The `securitypolicyviolation` event; console messages; a report endpoint on the API | **The event, collected by a wrapper of Playwright's `context` fixture** and checked after every test. It is standard and fires in Chromium and Firefox alike. Firefox writes its CSP messages to the browser's own console, which Playwright may not see; a report endpoint adds a route to the API for the tests' sake. **ESLint bans importing from `@playwright/test` in `e2e/tests/`**, since a journey that bypasses `support/test.ts` would run unguarded and still pass. <br>**Settled while building:** Firefox reports the injected style as `style-src-elem` with `blockedURI: "inline"`, as Chromium does, so the guard's test needs no second directive name. The guard's first run caught a real violation: zod 4 probes for eval support with `new Function("")` when it builds object schemas, at the module load of `@szop/shared`, and the CSP (which has no `'unsafe-eval'`) blocked it and reported it on every page load. The SPA now imports `apps/web/src/zod-config.ts` first in `main.tsx`; it calls `z.config({ jitless: true })`, and zod skips the probe under jitless. The CSP stays strict. The alternatives were ruled out: loosening the CSP with `'unsafe-eval'` is refused by [ADR 0012](0012-security-baseline.md), decision 8 and [ADR 0013](0013-visual-design.md), decision 9, and setting jitless in `packages/shared` would also switch the API off zod's fast path, where eval is allowed. Any new entry point that loads `@szop/shared` must import `zod-config.ts` first. |
| 8 | The first journey's name and lifetime | `health.spec.ts`; `uc-01-…` | **`health.spec.ts`,** named after the page: no use case is complete, and the `uc-NN-…` files of [ADR 0007](0007-testing-strategy.md), decision 17 are for use cases. It stays until the health page itself is replaced, tracked as [OP-087](https://github.com/luiki-dev/szop/issues/160) for PH-14. |
| 9 | What CI keeps of a failed run | The HTML report; the report and `test-results/` | **The HTML report only.** Playwright copies each failed test's trace and screenshot into it, so it is the one thing needed to read a failure. |

## Consequences

- **Every developer installs the browsers once,** with `playwright install --with-deps chromium firefox`, which needs `sudo` for the system libraries; the [setup guide](../development/setup.md) has the step ([#159](https://github.com/luiki-dev/szop/issues/159) is the owner's).
- **Every journey imports `test` and `expect` from `support/test.ts`** (ESLint refuses anything else in `e2e/tests/`) **and calls `expectAccessible` on every page** it reaches once the page has settled. No axe rule is turned off globally.
- **Each phase that completes a use case adds its `uc-NN` journey** ([ADR 0007](0007-testing-strategy.md), decision 4).
- **`health.spec.ts` goes with the health page** ([OP-087](https://github.com/luiki-dev/szop/issues/160), under [PH-14b](../roadmap.md#ph-14b-app-shell)).
- **The CSP guard covers the test's own context only** (decision 7). A journey that needs a second context, such as a second user in a sharing journey, must get a guarded one first ([OP-088](https://github.com/luiki-dev/szop/issues/162)).
- **Any new entry point that loads `@szop/shared` imports `zod-config.ts` first** (decision 7), or the CSP guard fails every journey on a zod eval probe. `apps/web` now depends on zod directly, for that file.
- **On Windows Subsystem for Linux (WSL), mirrored networking made connections to closed ports on `127.0.0.1` hang for about two minutes,** which stalled Playwright's pre-start check and its readiness polls (they have no timeout of their own). The owner switched WSL to network address translation (NAT) mode, and the troubleshooting note in the [setup guide](../development/setup.md) describes the symptom and the check.
- **The `e2e` job adds a few minutes to every code PR.** The install step's time and the job's time are measured in the PR (decision 5); `ci-ok` needs the job, so it is required without a change to GitHub's settings.
- **The open points changed:** the PH-07 part of [OP-010](https://github.com/luiki-dev/szop/issues/63) is ✅ done and the entry moves to [PH-15](../roadmap.md#ph-15-seed-catalog-read-only); [OP-012](https://github.com/luiki-dev/szop/issues/64) and [OP-057](https://github.com/luiki-dev/szop/issues/65) are closed by the PR; [OP-067](https://github.com/luiki-dev/szop/issues/27) moves to [PH-08](../roadmap.md#ph-08-container-image) (decision 1); the new [OP-087](https://github.com/luiki-dev/szop/issues/160) is under PH-14.
- **The living docs are updated:** the [testing guide](../development/testing.md), the [Playwright tool page](../development/tools/playwright.md), the [setup guide](../development/setup.md), the [CI/CD guide](../development/ci-cd.md), the [stack overview](../architecture/stack-overview.md), the [architecture](../architecture/architecture.md), the [glossary](../glossary.md) and the [roadmap](../roadmap.md).
