PH-18b · Screens and journey of registration and login (v5)

v5: "Link not valid" explains both cases, Send a new link is the main action · new /register/resend page (PH-18c).

A static mockup per state; the arrows say what moves you on. Everything is a page inside the app shell (decision A), phone shown, desktop at the end. PH-18c marks what PH-18c builds from this same design; the rest is PH-18b. Wording is a draft.

Fixed in the brainstorm so far: separate pages in the shell · password twice · display name (not unique) · link opened in another browser → the registering browser asks to log in (option 2) · a new sign-up replaces an unverified account with the same address (option 1) · the user's answer never depends on whether the address has an account.
