# PH-02 CI checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Check every PR in GitHub Actions (lint, formatting, types, the hook's tests, every commit message, the PR title, the workflow files), block the merge when a check fails, and turn on CodeQL and weekly Dependabot updates.

**Architecture:** Two workflows, one per trigger: `ci.yml` (a change-detection job, parallel check jobs skipped when their area did not change, and an aggregating `ci-ok` job, the one required check) and `pr-title.yml` (commitlint on the title). A composite action holds the shared install steps. `dependabot.yml` covers `npm` and `github-actions`. The owner applies the repository settings while the PR is open; a throwaway proof PR shows every gate failing.

**Tech Stack:** GitHub Actions on `ubuntu-24.04`; `actions/checkout` v7.0.1, `actions/setup-node` v7.0.0, `pnpm/action-setup` v6.1.0, `zizmorcore/zizmor-action` v0.6.4 (zizmor 1.30.1), actionlint 1.7.12; commitlint 21; Dependabot; CodeQL default setup.

**Spec:** `docs/superpowers/specs/2026-10-04-PH-02-ci-checks-design.md`. Read it before starting; this plan argues from it.

## Global Constraints

- Branch `ci/ci-checks`, already created, holding the spec commit; never commit to `main`; no worktree (`CLAUDE.md`, git workflow).
- **Execution: subagent-driven, with a fresh reviewer per task.** After a task's review passes and it is committed, push the branch (`git push`, `git push -u origin ci/ci-checks` the first time) and **pause** until the owner has reviewed that task; start the next task only when the owner says so. Pushing without an open PR runs no CI.
- **Pinned versions, exactly these** (all older than Dependabot's 7-day cooldown):
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`
  - `actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0`
  - `pnpm/action-setup@ea17c68df8912ef543352723c149a84f56e3d413 # v6.1.0`
  - `zizmorcore/zizmor-action@cc914d7f3750a2d13d75c7f184a1060aa0e9d482 # v0.6.4`
  - actionlint `1.7.12`, `actionlint_1.7.12_linux_amd64.tar.gz` SHA-256 `8aca8db96f1b94770f1b0d72b6dddcb1ebb8123cb3712530b08cc387b349a3d8`
- **Rules for every workflow** ([ADR 0010](../../decisions/0010-ci-cd.md), decisions 4 and 20): `runs-on: ubuntu-24.04`; `timeout-minutes` on every job; `permissions: {}` at the top and `contents: read` per job (nothing else in this phase); every action pinned to a full commit SHA with its version in a comment; `persist-credentials: false` on every checkout; nothing a PR author controls inside `${{ }}` in a `run:` script (pass it through `env:`); no `pull_request_target`, no `workflow_run`.
- **Job names are fixed:** `changes`, `lint`, `typecheck`, `test`, `commits`, `workflows`, `ci-ok`, `pr-title`. `ci-ok` and `pr-title` become required checks, which GitHub matches by name.
- **Before every commit that touches `.github/`,** run actionlint, zizmor (online, with `GH_TOKEN=$(gh auth token)`) and the schema checks from [Scratch tools](#scratch-tools); all must be clean.
- YAML is formatted by Prettier (the pre-commit hook does it); Markdown is never formatted by Prettier.
- Commit messages follow Conventional Commits with ADR 0009's nine types and the `scope-enum` list. Every commit ends with the trailers:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_011xfzGUiGZvCCzxyC2p2MyJ
  ```
- Docs follow `CLAUDE.md`'s writing style: niche acronyms spelled out on first use and added to the glossary; status icons before their word; requirements linked, never plain IDs; a `## Contents` section in documents over about 100 lines; an ADR that refines another is noted in three places (`CLAUDE.md`, the `docs/decisions/` bullet).
- Never merge a PR, never run `gh workflow run`, never delete a remote branch; do not work around `.claude/settings.json` or the push hook. Settings are read with `gh api` (GET only); only the owner changes them.

## Review Focus

Failure modes the spec implies that ordinary runs would not exercise; each has its check in the owning task.

1. **A PR that renames or deletes a code file into or next to Markdown** (`a.ts` → `a.md`, or only deleting `a.ts`): `changes` must still report `code=true`. Plain `git diff --name-only` shows only the new name of a rename. Check: Task 2, step 6 (`--no-renames`).
2. **A failed `changes` job:** every other job is then `skipped`, which alone would look green; `ci-ok` must fail (audit m10). Check: Task 2, step 7 (the `ci-ok` script on sample results) and Task 8 (a real run).
3. **A branch that merged `main` in (*Update branch*) before the PR's last push:** `commits` must check only the branch's own commits, accept the merge commit, and still reject one bad message among them. Check: Task 3, step 4.
4. **A PR title holding shell syntax** (`feat: add "x" $(touch pwned)`): it must reach commitlint as text and execute nothing. Check: Task 4, step 3.
5. **A Dependabot devDependency PR:** its real commit message (`build(deps-dev): …`, a body of tables and long links, a `Signed-off-by` trailer) must pass commitlint. Check: Task 1, steps 1 and 4.

## Findings since the spec

A prototype of every workflow file in a scratch clone, linted with actionlint and zizmor, validated against the schemas and exercised on a simulated PR merge, confirmed the design and turned up these details. ADR 0018 records them.

- **zizmor and actionlint disagree on local actions.** Since July 2026 GitHub Actions has a self-repository syntax, `uses: $/.github/actions/setup`, which loads the action at the running commit with no checkout. zizmor 1.30.1 reports every `./` reference as a `self-repository` finding (low severity, but any finding fails the job), while actionlint 1.7.12 rejects `$/` as invalid (support is an open PR, rhysd/actionlint#732). **The owner chose:** keep `./`, disable that one zizmor audit in `.github/zizmor.yml` with the reason, and switch to `$/` once actionlint supports it (new **OP-069**, PH-11, which also checks that Dependabot and CodeQL understand `$/`). This is decision 12 of ADR 0018.
- **zizmor-action runs zizmor's Docker image pinned by digest.** Its default `version: latest` means the newest version in the pinned action release's own digest list (1.30.1 for v0.6.4), so zizmor's version moves only when Dependabot bumps the action. Annotations need `annotations: true` as well as `advanced-security: false`. Online audits run with the job's read-only token; the prototype passed them.
- **The Markdown-only case cannot be shown on the proof PR:** it targets `main`, so its diff always includes the phase's own `.github/` and code changes. It is tested on a simulated merge in Task 2, and confirmed on the first Markdown-only PR after the merge, which joins **OP-067**. The spec's success criterion moves there.
- **The bad-commit-message break goes last on the proof PR:** the commit stays in the branch's history, so `commits` stays red for every later push.
- **`commits` does not wait for `changes`:** it runs on every PR regardless of the files, so it starts in parallel.
- **`changes` uses here-strings, not pipes, into `grep -q`:** with GitHub's default `bash -eo pipefail`, `printf … | grep -q` can fail when `grep` exits early and `printf` gets a broken pipe, which would set the output to `false`.
- **`ci-ok` uses `jq`,** preinstalled on GitHub's Ubuntu images, so the job needs no checkout and no permissions.
- **The current settings:** the default token is already read-only and *Allow GitHub Actions to create and approve pull requests* is already off. To change: SHA pinning (`sha_pinning_required: false`), the approval policy (`first_time_contributors`, to become all outside contributors), CodeQL (`not-configured`), and the `main` ruleset (no status check or code scanning rule yet).
- **CodeQL's Actions language** can only be detected once workflow files are on `main`. If the default setup offers only JavaScript/TypeScript before the merge, the owner adds Actions after it; this joins **OP-067**.
- **commitlint's default ignores** skip both `Merge branch 'main' into …` (GitHub's *Update branch*) and `Merge remote-tracking branch 'origin/main' into …` (a local merge).
- **The real Dependabot message** for audit m9: commit `89e1605e8753308afaef899f9fa596f9be168c03` of `Bruno-Mascarenhas/site-labmim`, a grouped `build(deps-dev)` update. Today it fails only on `scope-enum`.
- **Validation:** `check-jsonschema` with its built-in schemas (`vendor.dependabot`, `vendor.github-workflows`, `vendor.github-actions`) validates the files; it rejects an unknown key such as `cooldwn`.

- [ ] **Step 1: Write `.github/actions/setup/action.yml`**

```yaml
# The steps every job shares after the checkout (ADR 0010, decision 5).
# A composite action cannot check the repository out itself: GitHub must
# clone the repository before it can read an action stored in it.
name: Setup
description: Install pnpm, Node from .nvmrc and the dependencies, with the pnpm store cached.

runs:
  using: composite
  steps:
    # Reads the pnpm version from packageManager in package.json.
    - uses: pnpm/action-setup@ea17c68df8912ef543352723c149a84f56e3d413 # v6.1.0

    - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
      with:
        node-version-file: .nvmrc
        cache: pnpm

    # Fails instead of updating a lockfile that does not match package.json.
    - run: pnpm install --frozen-lockfile
      shell: bash
```

- [ ] **Step 3: Write `.github/workflows/ci.yml`**

```yaml
# Every quality check, on every PR to main and every push to main
# (ADR 0010, decisions 5-8; details in ADR 0018). The required check is ci-ok.
name: CI

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

permissions: {}

concurrency:
  group: ci-${{ github.event.pull_request.number || github.ref }}
  # A newer push to a PR replaces the older run; runs on main always finish.
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  changes:
    name: changes
    runs-on: ubuntu-24.04
    timeout-minutes: 5
    permissions:
      contents: read
    outputs:
      code: ${{ steps.detect.outputs.code }}
      workflows: ${{ steps.detect.outputs.workflows }}
    steps:
      # On a PR, the checkout is GitHub's test merge of the branch into main:
      # HEAD^1 is main, so the diff is exactly what the PR changes.
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 2
          persist-credentials: false

      - id: detect
        env:
          EVENT: ${{ github.event_name }}
        run: |
          if [ "$EVENT" != pull_request ]; then
            echo "Push to main: every check runs."
            code=true
            workflows=true
          else
            # --no-renames lists both names of a renamed file.
            files=$(git diff --name-only --no-renames HEAD^1 HEAD)
            printf 'Changed files:\n%s\n' "$files"
            # Code is anything that is not Markdown, so new file types are checked by default.
            # Here-strings, not pipes: with pipefail, an early grep -q exit could fail the pipe.
            if grep -qv '\.md$' <<<"$files"; then code=true; else code=false; fi
            if grep -qE '^\.github/(workflows|actions)/' <<<"$files"; then workflows=true; else workflows=false; fi
          fi
          echo "code=$code" >> "$GITHUB_OUTPUT"
          echo "workflows=$workflows" >> "$GITHUB_OUTPUT"
          echo "code=$code, workflows=$workflows"

  lint:
    name: lint
    needs: changes
    if: needs.changes.outputs.code == 'true'
    runs-on: ubuntu-24.04
    timeout-minutes: 10
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: ./.github/actions/setup
      - run: pnpm lint
      - run: pnpm format:check

  typecheck:
    name: typecheck
    needs: changes
    if: needs.changes.outputs.code == 'true'
    runs-on: ubuntu-24.04
    timeout-minutes: 10
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: ./.github/actions/setup
      - run: pnpm typecheck

  test:
    name: test
    needs: changes
    if: needs.changes.outputs.code == 'true'
    runs-on: ubuntu-24.04
    timeout-minutes: 10
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: ./.github/actions/setup
      - run: pnpm test

  ci-ok:
    name: ci-ok
    needs: [changes, lint, typecheck, test]
    if: always()
    runs-on: ubuntu-24.04
    timeout-minutes: 5
    permissions: {}
    steps:
      # Passes when changes succeeded and every other job succeeded or was
      # skipped. A failed changes job leaves the rest skipped (audit m10).
      - id: check
        env:
          NEEDS: ${{ toJSON(needs) }}
        run: |
          jq -r 'to_entries[] | "\(.key): \(.value.result)"' <<<"$NEEDS"
          jq -e '.changes.result == "success" and all(.[]; .result == "success" or .result == "skipped")' <<<"$NEEDS" > /dev/null
```
