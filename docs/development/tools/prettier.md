# Prettier

Prettier rewrites code into one consistent layout (quotes, line breaks, indentation, trailing commas), so formatting is never discussed in review. In Szop it formats the code and the configuration files, but not Markdown.

## Why Szop uses it

- **ESLint and Prettier, rather than Biome:** [ADR 0005](../../decisions/0005-development-environment.md), decision 12. Prettier is the common standard for formatting, and [ESLint](eslint.md) keeps the job of finding bugs.
- **The defaults, no custom options:** Prettier's own advice, since its few options exist mostly for historical reasons (<https://prettier.io/docs/option-philosophy>). Arguing about quotes or line width teaches nothing, so Szop takes the defaults.
- **Markdown excluded:** Prettier pads every table to its widest cell. On a trial copy of the docs the glossary grew from 39 KB to 93 KB, and one long cell rewrites the whole table in a diff. Prettier has no option to turn this off, so the docs keep their hand-made formatting. A Markdown linter that checks without reformatting is a candidate later ([OP-063](../../open-points.md#op-063)). See [ADR 0016](../../decisions/0016-toolchain-details.md).

## Configuration

**`.prettierrc.json`** holds `{}`: no options, so the defaults apply (double quotes, 80 columns, trailing commas).

**`.prettierignore`** lists what Prettier must not touch:

- `*.md`: Markdown, for the reason above.
- `pnpm-lock.yaml`: generated by pnpm, not written by hand.
- `coverage/`: the report `pnpm test:coverage` generates; see [Vitest](vitest.md).

Prettier also skips everything `.gitignore` lists (such as `node_modules/`), so those need no line here.

**`eslint-config-prettier`**, last in `eslint.config.js`, turns off the ESLint rules that would fight Prettier over layout, so the two tools never undo each other's work.

The Tailwind CSS class-sorting plugin arrives with the styling in PH-14.

## Everyday use

```bash
pnpm format                      # prettier --write .: rewrite every file Prettier supports that `.prettierignore` and `.gitignore` do not exclude
pnpm format:check                # only report files that are not formatted, change nothing; CI's lint job runs it
```

- In VS Code, the file is formatted on save (see [VS Code](vscode.md)).
- The pre-commit hook formats the staged files, so an unformatted file does not get committed (see [husky and lint-staged](husky-and-lint-staged.md)).
